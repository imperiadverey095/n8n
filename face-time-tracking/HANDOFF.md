# HANDOFF — контекст, решения и следующие шаги

Файл для передачи работы между сессиями (людям и ИИ-агентам). Дополняйте раздел «Журнал» при каждой значимой итерации.

## Задача

Реализовать «Time Management AI»: учёт прихода/ухода сотрудников по распознаванию лиц с фотографий, безопасное хранение отметок в БД по профилю сотрудника, детальные отчёты и табели (тип отчёта по умолчанию — `standard`), интеграция с HR-системами, настраиваемая отчётность для HR, соблюдение законодательства о персональных данных, возможность сотрудника проверять и исправлять свои записи.

Переменные из постановки: изображение для распознавания (`image` / `image_base64`), уникальный идентификатор сотрудника (`employee_id`), тип табеля (`type=standard|detailed|summary`).

* Самотест `db/900_selftest.sql` (7 групп, ASSERT) прогнан на реальном PostgreSQL 16 — **проходит**. Демо-данные `db/002_seed_demo.sql` проверены на чистой БД.

Валидатор `scripts/validate-workflows.mjs` сверил типы/версии всех нод с исходниками репозитория (437 нод) — **ок**. Конфигурации 19 ключевых нод дополнительно проверены на живом инстансе n8n пользователя через MCP `validate_node_config` — **valid**.
* Документация: README, docs/api.md, docs/reports.md, docs/hr-integration.md, docs/privacy-compliance.md, docs/n8n-node-versions.md; стенд docker-compose; скрипты импорта и smoke-теста.

## Ключевые решения и почему

| Решение | Почему |
|---|---|
| **CompreFace (self-hosted) как провайдер распознавания** | биометрия не покидает периметр; открытая лицензия; REST API с subject = `employee_id`; `SAVE_IMAGES_TO_DB=false` — хранятся только эмбеддинги. Альтернативы (AWS Rekognition, Azure Face) заменяются в трёх HTTP-нодах. |
| **Вся логика в SQL-функциях `fn_*`** | атомарность (FOR UPDATE на сотруднике), единые правила для всех входов (лицо/ручная/корректировка), тестируемость без n8n, воркфлоу остаются короткими. |
| **Фото передаётся как binary (multipart), не base64 в JSON** | снимок не оседает в данных выполнений n8n; в БД только sha256-хэш (нода Crypto) и схожесть. |
| **Токены API в БД с sha256, роли device/employee/hr/system** | один механизм аутентификации на все вебхуки без Enterprise-функций n8n; сотрудник видит только себя по токену, а не по параметру запроса. |
| **Идемпотентность + антидребезг + `maxSessionHours` в `fn_clock`** | терминалы шлют дубли и офлайн-очереди; чередование приход/уход не должно «закрывать» смену через сутки. |
| **Обязательное согласие + небиометрическая альтернатива (ручная отметка)** | требования GDPR ст. 9 / 152-ФЗ ст. 11; в РФ 572-ФЗ может запретить коммерческую биометрию вне ЕБС/КБС — система должна работать и без распознавания. |
| **Корректировки не удаляют историю** | старое событие помечается `corrected`/`voided` со ссылкой `superseded_by`; подотчётность. |
| **Outbox-паттерн для HR-интеграции** | доставка «хотя бы один раз», повтор с экспоненциальной паузой, независимость от конкретной HR-системы. |
| **Генератор JSON вместо ручного JSON** | 146 нод; детерминированные id (sha1 от имени) → чистые диффы; версии нод в одном месте. |
| **Версии нод «не самые новые»** (Postgres 2.5, If 2.2, HTTP 4.2, Webhook 2) | совместимость и с форком, и с облаком; Postgres ≥ 2.5 нужен ради массива в Query Parameters (JSON-аргументы). |

## Что НЕ сделано / ограничения

* Воркфлоу не запускались end-to-end с реальным CompreFace (в песочнице нет фото и инстанса) — проверены статически и валидатором инстанса. Первый прогон `scripts/smoke-test.sh` на стенде — **первый следующий шаг**.
* Нет liveness-детекции (защиты от фото на телефоне): CompreFace её не даёт. Рекомендация — SDK терминала с liveness, оценка передаётся в `liveness_score`.
* Нет UI: сотрудники и HR работают через API (киоск, мобильное приложение, HR-портал). Быстрый вариант UI — n8n Form Trigger для формы корректировки или страница на любом фронтенде.
* Расчёт табеля покрывает типовые правила (обед, опоздания, сверхурочные, смены через полночь). Ночные надбавки, округления, праздники, отпуска/больничные (статусы «уважительного отсутствия») — не реализованы; место для них — `fn_daily_summary` + таблица календаря.
* Юридическая часть (DPIA, тексты согласий, применимость 572-ФЗ) требует юриста.

## Следующие шаги (по приоритету)

1. Поднять стенд (`docker compose up -d`), создать credentials, импортировать воркфлоу, прогнать `scripts/smoke-test.sh` с реальными фото; исправить всё, что всплывёт на живом CompreFace (формат ответов проверен по документации 1.2, но не в бою).
2. Подобрать `similarityThreshold` / `detProbThreshold` на реальном парке терминалов; включить liveness на стороне терминала.
3. Подключить реальную HR-систему в воркфлоу 06 (маппинг payload) и настроить SMTP.
4. Добавить производственный календарь и типы отсутствий (отпуск/больничный/командировка) в расчёт табеля.
5. Форма/приложение для сотрудников (корректировки) и панель HR (очередь запросов) — например, на n8n Forms или отдельном фронтенде.
6. Нагрузочная проверка `fn_clock` (FOR UPDATE по сотруднику — узкое место только при параллельных отметках одного человека, что нормально).

## Как продолжать работу

* Логика → `db/001_schema.sql` + сценарий в `db/900_selftest.sql` → `scripts/test-db.sh`.
* Воркфлоу → `scripts/workflows/*.mjs` → `node scripts/build-workflows.mjs && node scripts/validate-workflows.mjs` → коммит JSON вместе с исходниками.
* Версии нод и имена credentials — `scripts/lib/builder.mjs`.
