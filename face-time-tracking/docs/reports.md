# Отчёты и табели

Все вычисления — в БД (`db/001_schema.sql`): `fn_sessions` → `fn_daily_summary` → `fn_timesheet`. Воркфлоу n8n только форматируют результат, поэтому цифры в JSON, CSV, HTML и в ежемесячной рассылке всегда совпадают. Правила проверены самотестом `db/900_selftest.sql` (блок 4).

## Как считаются показатели

| Показатель | Правило |
|---|---|
| **Сессия** | `check_in` и следующее за ним событие, если это `check_out`. Если следующее событие снова `check_in` (или его нет) — сессия **незакрытая** (`incomplete`), её длительность не учитывается. |
| **Рабочая дата** | дата `check_in` в часовом поясе сотрудника; смена через полночь целиком относится к дню её начала. |
| **Плановые минуты** | `end − start − break_minutes` из `work_schedule`, только для дней из `days`. |
| **Отработано** | сумма сессий за день. Если суммарные перерывы между сессиями меньше `break_minutes`, недостающая часть обеда **удерживается автоматически** (сотрудник не отмечал обед). `break_minutes: 0` отключает удержание. |
| **Опоздание** | `first_in − start` (мин), только в плановые дни. |
| **Ранний уход** | `end − last_out`, только если день закрыт. |
| **Сверхурочно** | `отработано − план` в плановые дни; в выходные — всё отработанное время. |
| **Статус дня** | `present`, `late` (приход позже плана более чем на минуту), `incomplete`, `absent` (плановый день без отметок), `day_off`. |

Скорректированные (`corrected`) и аннулированные (`voided`) события в расчётах не участвуют — участвуют события, созданные при одобрении корректировки (`source = correction`).

## Типы отчётов

### `summary` — итоги по сотрудникам
Одна строка на сотрудника: плановых дней, отработано дней, отсутствий, незакрытых смен, опозданий (дней), план/факт/сверхурочно (часы и минуты), суммарные минуты опозданий и ранних уходов.

### `standard` — табель по дням
Для каждого сотрудника строка на каждый календарный день периода: дата, статус, первый приход, последний уход, число сессий, отработано, перерывы, план, опоздание, ранний уход, сверхурочно. Плюс итоги. В CSV — плоские строки с `employee_id`/`full_name`/`department`.

### `detailed` — полная детализация
`standard` + все сессии (с идентификаторами событий и источниками `face`/`manual`/`correction`/`import`) + запросы корректировок за период с решениями HR. Используется для разбора спорных ситуаций и аудита.

## Форматы

* **json** — `{ ok, report: {type, format, from, to, employees, generated_at, requested_by}, data: [...] }`. В `detailed` данные возвращаются «как есть» из `fn_timesheet` (сырые ISO-даты, минуты).
* **csv** — разделитель `;` (Config → `csvDelimiter`), кодировка UTF-8, времена в часовом поясе сотрудника. В `detailed` строки помечены колонкой `section` (`day`/`session`/`correction`).
* **html** — самодостаточная страница со сводкой и таблицами по каждому сотруднику; подходит для печати и для вложения в письмо.

## Расписания (воркфлоу 05)

* **1-е число, 06:00 UTC** — табель `standard` за прошлый месяц по всем сотрудникам: письмо HR со сводкой в теле и CSV во вложении.
* **Понедельник, 08:00 UTC** — письмо каждому сотруднику, у которого за прошлую неделю есть незакрытые смены или отсутствия в плановые дни, со ссылкой на самообслуживание.

## Настройка под HR-менеджера

* Другой период/фильтр — параметры запроса `GET /timetrack/reports` (см. [api.md](api.md)).
* Другие колонки/язык/порядок — функции `dayRows`, `summaryRow`, `*_COLUMNS` в `scripts/workflows/03-attendance-reports.mjs` (общий модуль `REPORT_LIB_JS` используется и в рассылке).
* Другие правила (например, округление до 15 минут, ночные надбавки) — в `fn_daily_summary` в `db/001_schema.sql`; добавьте проверку в `db/900_selftest.sql`.
* Excel/Google Sheets вместо CSV — замените ноду *Convert To CSV* на операцию `xlsx` той же ноды или на ноду Google Sheets.
