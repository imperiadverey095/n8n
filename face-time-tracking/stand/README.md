# Локальный стенд без Docker

Поднимает систему учёта целиком на одной машине: настоящие n8n и PostgreSQL,
а три внешних сервиса — распознавание лиц, приёмник кадровой системы и SMTP —
заменены заглушками. Нужен, когда демона Docker нет или когда надо прогнать
сквозной сценарий быстрее, чем поднимается `docker compose`.

Заглушки повторяют контракты, а не поведение: распознавание сопоставляет снимки
по sha256, поэтому «своим» считается ровно тот кадр, который был зарегистрирован.
Ответ настоящего CompreFace так не проверить — для этого нужен `docker-compose.yml`
из корня проекта.

## Что нужно заранее

* Node.js 24 и новее — n8n 2.x на Node 22 не запускается. Если Node лежит
  отдельно, добавьте его в `PATH` внутри `env.sh`.
* PostgreSQL 16 с готовым кластером (`PGDATA`) и базой `timetrack`.
* Ничего дополнительно устанавливать не нужно: подстановку значений в шаблон учётных
  данных делает `render-credentials.py`, а не `envsubst`.
* n8n, установленный глобально: `npm i -g n8n`.

## Быстрый старт

```bash
cd face-time-tracking/stand
cp .env.example .env          # задайте N8N_ENCRYPTION_KEY и PGDATA
./up.sh                       # PostgreSQL, три заглушки, n8n
./bootstrap.sh                # схема базы, тестовые снимки, токены
./sync-workflows.sh           # перенос воркфлоу с локальными адресами
./import.sh                   # импорт и публикация
./down.sh && ./up.sh          # перезапуск n8n, чтобы вебхуки зарегистрировались
./tokens.sh employee EMP-001  # после первой регистрации сотрудника
./e2e.sh                      # сквозной сценарий из 10 шагов
./verify.sh                   # состояние базы, только SELECT
```

Повторный `./import.sh` обновляет воркфлоу на месте: у них постоянные
идентификаторы, а `import:workflow` делает upsert по полю `id`.

## Что где лежит

Данные стенда живут вне репозитория, в `STAND_HOME` (по умолчанию `~/n8n-stand`):
база n8n, письма (`mail/*.eml`), файлы токенов, журналы и перенесённые воркфлоу.
В репозитории — только скрипты.

| Файл | Назначение |
|---|---|
| `env.sh` | окружение; значения секретов берёт из `stand/.env` |
| `up.sh` / `down.sh` | поднять и остановить службы (идемпотентно) |
| `bootstrap.sh` | схема базы, тестовые снимки, токены (`--reset` пересоздаёт схему) |
| `tokens.sh` | выпуск отдельного токена в файл с правами 600 |
| `sync-workflows.sh` | перенос воркфлоу с подменой адресов на локальные заглушки |
| `import.sh` | импорт учётных данных и воркфлоу, публикация каждого |
| `e2e.sh` | сквозной сценарий: регистрация, отметка, отчёты, корректировка |
| `verify.sh` | состояние базы: сотрудники, события, заявки, очередь, аудит |
| `compreface-stub.mjs` | заглушка распознавания, сопоставление по sha256 снимка |
| `hr-sink.mjs` | приёмник событий кадровой системы со счётчиком |
| `smtp-sink.mjs` | SMTP-приёмник, складывает письма в `$STAND_HOME/mail` |

## Секреты

`stand/.env` не коммитится, значения в него подставляете вы. `credentials.json`
собирается из `credentials.json.template` при каждом `import.sh` и тоже остаётся
за пределами репозитория. Значения токенов доступа никуда не печатаются: `fn_issue_token`
возвращает их прямо в файл с правами 600, а скрипты читают файл, а не аргумент
командной строки — иначе токен виден в списке процессов.

Ключи заглушек (`CF_API_KEY`, `HR_API_TOKEN`, `SMTP_PASSWORD`) ничего не защищают:
заглушки слушают только localhost. Но они должны совпадать в заглушке и в учётных
данных, поэтому задаются в одном месте.

## Подводные камни

* **Заглушка распознавания держит соответствие «снимок → сотрудник» в памяти.**
  После её перезапуска отметка по лицу перестаёт работать, пока сотрудник не
  зарегистрирован заново. Сбрасывайте её вместе с базой, иначе прогон увидит
  результат предыдущего.
* **Приёмник кадровой системы тоже считает в памяти.** Нулевой счётчик после
  перезапуска не означает, что события не доставлялись — смотрите статусы в
  `timetrack.hr_sync_outbox`.
* **Вебхуки регистрируются при старте n8n.** После импорта воркфлоу n8n надо
  перезапустить, иначе новые пути отвечают 404.
* **Строка `Processed 0 published workflows` в журнале n8n** относится к индексу
  зависимостей, а не к регистрации вебхуков. Проверяйте запросом: обращение к
  `/webhook/timetrack/clock` без токена должно вернуть 401, а не 404.
* **`import.sh` идёт минуты.** Публикация делается отдельной командой на каждый
  воркфлоу, и каждый вызов CLI поднимает окружение n8n заново. Это нормально.
* **Без IPv6** запуск падает с «address '::' is not available» — за это отвечает
  `N8N_LISTEN_ADDRESS=127.0.0.1` в `env.sh`.
